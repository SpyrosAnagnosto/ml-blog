# Molecular representations — Morgan fingerprints and ChemBERTa

In our previous lessons, we learned how to inspect ESOL, identify its solubility targets, find duplicate molecules, and understand the importance of molecular data splitting.

Now we're ready to give an answer to our first question:

**How do we turn a chemical structure into something a machine learning model can understand?**

We'll explore two approaches:

- Morgan fingerprints: describe the local chemical structures present in a molecule using a fixed-length numerical vector.
- ChemBERTa: interprets a molecule's SMILES representation with a pretrained transformer, learning numerical representations from chemical sequences.

## Part A - Morgan fingerprints

A Morgan fingerprint is a numerical description of the chemical environments found around atoms in a molecule.

The main idea is simple:

1. Start with each atom.
2. Describe the atom and its local surroundings.
3. Expand the surroundings by a specified number of bonds.
4. Generate numerical identifiers for these environments.
5. Optionally compress the identifiers into a fixed-length fingerprint vector.

The commonly used Extended-Connectivity Fingerprints (ECFPs) are based on this general approach. Morgan fingerprints of radius 2 using atom-identity-style invariants are commonly referred to as ECFP4-like fingerprints.


**Generating fingerprints with RDKit**

```python
from rdkit import Chem, rdBase
from rdkit.Chem import rdFingerprintGenerator

print("RDKit version:", rdBase.rdkitVersion)

mol = Chem.MolFromSmiles("CCO")

generator = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=128
)

fingerprint = generator.GetFingerprint(mol)

print("Number of atoms:", mol.GetNumAtoms())
print("Fingerprint length:", len(fingerprint))
print("Active bits:", fingerprint.GetNumOnBits())
print("Bit positions:", list(fingerprint.GetOnBits()))
```

```text
RDKit version: 2026.09.1
Number of atoms: 3
Fingerprint length: 128
Active bits: 6
Bit positions: [2, 33, 38, 39, 80, 94]
```

Let's understand every line.

- Number of atoms: 3 — RDKit parsed the three explicit atoms in CCO.
- Fingerprint length: 128 — we requested a vector with 128 positions.
- Active bits: 6 — only six positions are set to 1.
- Bit positions: [...] — those are the indices of the active positions.

The other 122 positions contain 0.

We can display the vector as a grid. The columns are fingerprint positions, not literal atoms.

![Ethanol’s 128-bit Morgan fingerprint with six active positions]({{ "/assets/images/molecular-representations/cell-3-image.png" | relative_url }})

The vector length is not the number of atoms. A molecule with three atoms can have a 128-bit fingerprint, as can a molecule with 30 atoms.

An active bit is not necessarily a unique named chemical substructure. It indicates that one or more hashed molecular environments activated that position. Different environments can sometimes activate the same position.

**What happens when we change the radius?**

```python
mol = Chem.MolFromSmiles("CCO")

for radius in [0, 1, 2, 3]:
    gen = rdFingerprintGenerator.GetMorganGenerator(
        radius=radius,
        fpSize=128
    )

    fp = gen.GetFingerprint(mol)

    print(
        f"Radius {radius}: "
        f"{list(fp.GetOnBits())}"
    )
```

```text
Radius 0: [33, 39, 80]
Radius 1: [2, 33, 38, 39, 80, 94]
Radius 2: [2, 33, 38, 39, 80, 94]
Radius 3: [2, 33, 38, 39, 80, 94]
```

Radius 1, 2 and 3 all produced the same fingerprint for ethanol.

Why? Ethanol is a tiny molecule. Increasing the radius cannot keep adding new, informative neighborhoods indefinitely. RDKit's Morgan implementation also suppresses certain redundant environments by default.

For larger molecules, changing the radius can introduce many additional environments.

We now inspect which atoms generated the bits.

```python
mol = Chem.MolFromSmiles("CCO")

gen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=128
)

info = rdFingerprintGenerator.AdditionalOutput()
info.CollectBitInfoMap()

fp = gen.GetFingerprint(
    mol,
    additionalOutput=info
)

for bit, environments in sorted(
    info.GetBitInfoMap().items()
):
    print(bit, environments)
```

```text
2 ((1, 1),)
33 ((0, 0),)
38 ((0, 1),)
39 ((2, 0),)
80 ((1, 0),)
94 ((2, 1),)
```

2 ((1, 1),) means that fingerprint bit 2 was generated by an environment centered at atom index 1, using radius 1.

We saw earlier that ethanol's atoms have indices 0, 1 and 2. RDKit's bitInfoMap gives us a useful connection between the abstract vector and the original chemical structure.

**What does fingerprint size mean?**

We've been using fpSize=128, but real experiments often use 1,024 or 2,048 bits.

Fingerprint size is the number of available positions in the output vector.

What changes when we alter this parameter?

```python
mol = Chem.MolFromSmiles("CCO")

for size in [8, 16, 128, 2048]:
    gen = rdFingerprintGenerator.GetMorganGenerator(
        radius=2,
        fpSize=size
    )

    fp = gen.GetFingerprint(mol)

    print(
        f"Size {size}: "
        f"{list(fp.GetOnBits())}"
    )
```

```text
Size 8: [0, 1, 2, 6, 7]
Size 16: [0, 1, 2, 6, 7, 14]
Size 128: [2, 33, 38, 39, 80, 94]
Size 2048: [80, 222, 294, 807, 1057, 1410]
```

The actual chemistry hasn't changed. Only the compression into the fingerprint vector has changed.

Why does the 8-bit fingerprint have five active bits while the larger fingerprints have six?

Because of something called a **hash collision**.

**Hashing and collisions**

A hash function takes information about a chemical environment and converts it into a numerical identifier.
In the fixed-length Morgan representation, those identifiers are mapped to positions in the output vector.
A simplified way to understand the mapping is:

$$
\text{bit position} = \text{environment identifier} \bmod \text{fingerprint size}
$$

For example, suppose two different chemical environments have identifiers 22 and 30.
If the fingerprint has eight bits:

$$
22 \bmod 8 = 6
$$

$$
30 \bmod 8 = 6
$$

Both activate bit 6.
That is a hash collision.

**A real collision in ethanol**

We'll use an intentionally tiny 8-bit fingerprint.

```python
mol = Chem.MolFromSmiles("CCO")

gen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=8
)

info = rdFingerprintGenerator.AdditionalOutput()
info.CollectBitInfoMap()

fp = gen.GetFingerprint(
    mol,
    additionalOutput=info
)

print("Active bits:", list(fp.GetOnBits()))
print("Bit 6 environments:", info.GetBitInfoMap()[6])
```

```text
Active bits: [0, 1, 2, 6, 7]
Bit 6 environments: ((0, 1), (2, 1))
```

Bit 6 was activated by two distinct atomic environments: one centered on atom 0 with radius 1, the other centered on atom 2 with radius 1.

At 16 bits, these environments map to different positions—6 and 14.

Now we can see why increasing fingerprint size can help: it reduces the chance that unrelated environments are forced to share positions.

However, a larger fingerprint doesn't necessarily improve prediction. It can increase memory requirements and produce a sparser input representation.

For our later experiments, useful configurations to investigate would be radius 2 with 1,024 or 2,048 bits, and possibly radius 3 for comparison.

**Binary fingerprints versus count fingerprints**

So far we've used binary vectors.
They record whether a feature appears at least once:

$$
[0, 1, 0, 1, 0, ...]
$$

But what if a molecular environment appears several times?
A binary vector records presence, not the number of occurrences. A count fingerprint can retain counts instead:

$$
[0, 3, 0, 1, 0, ...]
$$

RDKit supports both types:

```python
gen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=128
)

mol = Chem.MolFromSmiles("CCO")

binary_fp = gen.GetFingerprint(mol)
count_fp = gen.GetCountFingerprint(mol)

print("Binary active bits:", binary_fp.GetNumOnBits())
print("Count entries:", count_fp.GetNonzeroElements())
```

```text
Binary active bits: 6
Count entries: {2: 1, 33: 1, 38: 1, 39: 1, 80: 1, 94: 1}
```

Count fingerprints are worth testing eventually, particularly when repeated substructures carry useful information. But they are a different feature specification and should be recorded separately from binary fingerprints.

**Tanimoto similarity: are two molecules structurally similar?**

Now that we can generate fingerprints, we can compare them.
A widely used similarity measure for binary molecular fingerprints is the Tanimoto coefficient, which is the Jaccard similarity of the sets of active bits.
Given two fingerprints $$A$$ and $$B$$:

$$
T(A,B)=\frac{|A\cap B|}{|A\cup B|}
$$

Here:

- $$\lvert A\cap B\rvert$$ is the number of bit positions active in both fingerprints.
- $$\lvert A\cup B\rvert$$ is the number of positions active in at least one fingerprint.

The result ranges from 0 to 1.
A score of 1 means that the two fingerprints are identical; it does not necessarily prove that the molecules are identical. A score of 0 means that these particular fingerprints share no active bits.

Let's compare ethanol (CCO) with 1-propanol (CCCO) using radius 2 and 128 bits.

The RDKit calculation gives:

Active ethanol bits: 6

Active 1-propanol bits: 8

Shared active bits: 5

Total distinct active bits: 9

Tanimoto similarity: 0.5556

Therefore:

$$
T(\text{ethanol},\text{1-propanol})=\frac{5}{9}\approx0.556
$$

```python
from rdkit import Chem, DataStructs
from rdkit.Chem import rdFingerprintGenerator

gen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=128
)

m1 = Chem.MolFromSmiles("CCO")
m2 = Chem.MolFromSmiles("CCCO")

fp1 = gen.GetFingerprint(m1)
fp2 = gen.GetFingerprint(m2)

similarity = DataStructs.TanimotoSimilarity(fp1, fp2)

print("Shared bits:", len(
    set(fp1.GetOnBits()) & set(fp2.GetOnBits())
))
print("Tanimoto:", round(similarity, 4))
```

```text
Shared bits: 5
Tanimoto: 0.5556
```

**Compare several molecules**

Note: These scores are specific to the fingerprint algorithm, radius, bit size and RDKit settings.

```python
molecules = {
    "Ethanol": "CCO",
    "1-Propanol": "CCCO",
    "Dimethyl ether": "COC",
    "Benzene": "c1ccccc1",
    "Toluene": "Cc1ccccc1",
}

fingerprints = {
    name: gen.GetFingerprint(Chem.MolFromSmiles(s))
    for name, s in molecules.items()
}

pairs = [
    ("Ethanol", "Ethanol"),
    ("Ethanol", "1-Propanol"),
    ("Ethanol", "Dimethyl ether"),
    ("Ethanol", "Benzene"),
    ("Benzene", "Toluene")
]

for a, b in pairs:
    score = DataStructs.TanimotoSimilarity(
        fingerprints[a],
        fingerprints[b]
    )
    print(f"{a} vs {b}: {score:.4f}")
```

```text
Ethanol vs Ethanol: 1.0000
Ethanol vs 1-Propanol: 0.5556
Ethanol vs Dimethyl ether: 0.1111
Ethanol vs Benzene: 0.0000
Benzene vs Toluene: 0.3000
```

**Tanimoto similarity changes with fingerprint size**

![Tanimoto similarity comparison across fingerprint sizes]({{ "/assets/images/molecular-representations/cell-18-image.png" | relative_url }})

With only 16 bits, hash collisions raise the apparent similarity between these molecules.
This is one reason to use adequately sized fingerprints. It's also why similarity scores should only be compared when fingerprint settings are consistent.

Imagine a molecule in the test set that is almost identical to one in the training set.
A model may find its solubility easier to predict because similar chemical substructures often share relevant properties.
We can use Morgan fingerprints and Tanimoto similarity to answer:
How structurally similar are the test molecules to the molecules used for training?
That's a very useful diagnostic when comparing random and scaffold splits.

## Part B — ChemBERTa

We'll use the specific checkpoint seyonec/ChemBERTa-zinc-base-v1

Morgan fingerprints are calculated from the molecular graph using predetermined rules.
ChemBERTa takes a different approach: it uses a transformer architecture pretrained on large collections of SMILES strings.

There are two important differences from Morgan fingerprints:

First, ChemBERTa's numerical representations are learned from data. They aren't predefined by a fixed fingerprinting algorithm.

Second, the transformer processes an ordered sequence of tokens, rather than directly receiving the complete molecular graph.
It may learn useful patterns related to molecular structure, but it does not automatically understand every chemical property or have access to a molecule's full 3D geometry.

```python
from transformers import AutoTokenizer

checkpoint = "seyonec/ChemBERTa-zinc-base-v1"

tokenizer = AutoTokenizer.from_pretrained(checkpoint)

examples = ["CCO", "OCC", "CCCO", "c1ccccc1"]

for smiles in examples:
    encoded = tokenizer(smiles)

    print("SMILES:", smiles)
    print("Tokens:", tokenizer.convert_ids_to_tokens(
        encoded["input_ids"]
    ))
    print("Token IDs:", encoded["input_ids"])
    print()
```

**An interesting comparison: CCO versus OCC**

Remember that both strings represent ethanol.
Our RDKit calculation confirms they produce identical Morgan fingerprints:

```python
gen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=128
)

fp_a = gen.GetFingerprint(Chem.MolFromSmiles("CCO"))
fp_b = gen.GetFingerprint(Chem.MolFromSmiles("OCC"))

print("Fingerprints equal:", fp_a == fp_b)
print("Tanimoto:", DataStructs.TanimotoSimilarity(
    fp_a, fp_b
))
```

```text
Fingerprints equal: True
Tanimoto: 1.0
```

But ChemBERTa sees different token sequences, even though they describe the same molecule.

The pretrained model may produce different embeddings for the two strings.

This is one reason that SMILES standardization and SMILES augmentation are important research topics.

For our eventual experiments, we'll need a deliberate policy for which SMILES representation is passed to ChemBERTa.

**What does ChemBERTa actually output?**

The input is a sequence of token IDs. A transformer encoder then creates a vector for each input token.
For our checkpoint, the configuration specifies:

|Property|Value|
|--------|-----|
|Transformer layers | 6|
|Attention heads |12|
|Hidden dimension |768|
|Vocabulary size |767|
|Model architecture|RoBERTa-style|

These are the checkpoint's published configuration values—not generic specifications for every ChemBERTa model. 


Suppose we tokenize a single molecule into three tokens:

The final hidden-state tensor will have shape:

$$
(1,\ 3,\ 768)
$$

The dimensions mean:

- 1 molecule in the batch.
- 3 tokens in its tokenized sequence.
- 768 learned numerical features for each token.

**Extract representations**

```python
import torch
from transformers import AutoTokenizer, AutoModel

checkpoint = "seyonec/ChemBERTa-zinc-base-v1"

tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModel.from_pretrained(checkpoint)

model.eval()

smiles_list = ["CCO", "OCC", "CCCO"]

inputs = tokenizer(
    smiles_list,
    return_tensors="pt",
    padding=True,
    truncation=True
)

with torch.no_grad():
    outputs = model(**inputs)

token_embeddings = outputs.last_hidden_state

# Mean pooling over non-padding tokens
mask = inputs["attention_mask"].unsqueeze(-1)

molecule_embeddings = (
    (token_embeddings * mask).sum(dim=1)
    / mask.sum(dim=1).clamp(min=1)
)

print("Token embeddings:", token_embeddings.shape)
print("Molecule embeddings:", molecule_embeddings.shape)
print("One molecule's embedding:",
      molecule_embeddings[0].shape)
```

The 768-dimensional vector is a possible frozen ChemBERTa representation for a molecule.

Mean pooling is a practical baseline, not the only correct way to obtain molecular embeddings. We can later compare pooling strategies, including using a special-token representation and models trained specifically for molecular embeddings.

## Part C — Connecting representations back to MoleculeNet

In the previous post we wrote

```python
tasks, datasets, transformers = dc.molnet.load_delaney(
    featurizer="ECFP",
    splitter=None,
    transformers=[]
)
```

What does featurizer="ECFP" actually do?

In the current DeepChem MoleculeNet loader implementation, the ECFP shortcut is defined using:

```python
dc.feat.CircularFingerprint(size=1024)
```

The CircularFingerprint default radius is 2. 

That means the representation is approximately:

- Morgan/ECFP-style circular fingerprints.
- Radius 2.
- 1,024 bits.
- Binary representation.

Compare it with our manually created Morgan fingerprint:

```python
generator = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=1024
)
```

These use corresponding fingerprint settings, although exact implementation and version details should be checked when comparing features across libraries.

Note: dc.feat.CircularFingerprint() on its own defaults to 2,048 bits, whereas the MoleculeNet ECFP shortcut explicitly specifies 1,024 bits.

We should always record our feature parameters.

**Generate Morgan fingerprints for all ESOL compounds**

```python
import pandas as pd
import numpy as np

from rdkit import Chem, DataStructs
from rdkit.Chem import rdFingerprintGenerator

url = (
    "https://deepchemdata.s3-us-west-1.amazonaws.com/"
    "datasets/delaney-processed.csv"
)

df = pd.read_csv(url)
df["smiles"] = df["smiles"].str.strip()

TARGET = "measured log solubility in mols per litre"

generator = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,
    fpSize=1024
)

molecules = [
    Chem.MolFromSmiles(s)
    for s in df["smiles"]
]

assert all(mol is not None for mol in molecules)

fingerprints = []

for mol in molecules:
    fp = generator.GetFingerprint(mol)
    arr = np.zeros(1024, dtype=np.int8)
    DataStructs.ConvertToNumpyArray(fp, arr)
    fingerprints.append(arr)

X = np.stack(fingerprints)
y = df[TARGET].to_numpy()

print("X shape:", X.shape)
print("y shape:", y.shape)
print("Fingerprint values:", np.unique(X))
print("First molecule active bits:",
      np.flatnonzero(X[0]).size)
```

```text
X shape: (1128, 1024)
y shape: (1128,)
Fingerprint values: [0 1]
First molecule active bits: 44
```

`X` is the molecular representation. 

`y` is the measured solubility target.

We have now prepared the input features without training any predictive model.

A pretrained molecular transformer is not automatically better than Morgan fingerprints.

Morgan fingerprints explicitly encode local chemical connectivity and are often strong baselines, especially when datasets are small.

ChemBERTa brings learned representations from its pretraining data, but their usefulness depends on factors such as how closely the pretraining chemistry matches the prediction task, the checkpoint, the representation extraction method, and whether fine-tuning is allowed.

These are precisely the questions our later experiments can investigate.
